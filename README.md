# whisperX на macOS: стенд для русской телефонии

Локальный стенд, чтобы проверять качество распознавания русской речи
телефонного качества: [whisperX](https://github.com/m-bain/whisperX) +
генератор синтетического тестового звонка.

Разворачивался на Apple Silicon (macOS, 24 ГБ RAM) 07.10.2026. Здесь записано,
что реально понадобилось — включая три места, где всё спотыкается.

## Состав

| | |
|---|---|
| whisperx | 3.8.6 (PyPI, BSD-2) |
| torch / torchaudio | 2.8.0 |
| Python | 3.12.14 через `uv` |
| ffmpeg | 9.0.2 (Homebrew) |
| `.venv` | ~980 МБ, кеш моделей ещё ~2,8 ГБ |

## Установка

```bash
brew install ffmpeg
uv venv --python 3.12
VIRTUAL_ENV=.venv uv pip install whisperx
```

Системный Python в macOS — 3.9, он не подойдёт: whisperX требует ≥3.10.
`uv` сам поставит нужную версию, трогать системную не нужно.

### Данные NLTK

whisperX на этапе выравнивания режет текст на предложения через NLTK и требует
пакет `punkt_tab`. Если штатный `nltk.download('punkt_tab')` не проходит
(например, его блокирует сетевая политика), данные можно забрать напрямую:

```bash
mkdir -p ~/nltk_data/tokenizers && cd ~/nltk_data/tokenizers
curl -sSL -o punkt_tab.zip \
  https://raw.githubusercontent.com/nltk/nltk_data/gh-pages/packages/tokenizers/punkt_tab.zip
unzip -qo punkt_tab.zip && rm punkt_tab.zip
```

Грабли: без этого пакета прогон падает **уже после распознавания**, на стадии
выравнивания. Транскрипт при этом теряется целиком, а в логе наверху видно, что
модель отработала — легко решить, что виновата она.

## Тестовый звонок

Реальные записи разговоров — персональные данные, на стенде им не место.
`make_sample.sh` собирает синтетический звонок оператора с клиентом:

- macOS `say` голосом Milena — единственный русский голос в системе
- второй говорящий получается сдвигом тона через ffmpeg
- сверху полоса 300–3400 Гц и передискретизация в 8 кГц

Последний шаг важнее, чем кажется: на студийном аудио метрики всегда красивее,
чем на телефонном, и стенд начинает врать в свою пользу.

```bash
./make_sample.sh          # → audio/zvonok.wav
```

## Запуск

```bash
.venv/bin/whisperx audio/zvonok.wav \
  --language ru --model small --compute_type int8 --device cpu \
  --batch_size 8 --output_dir out --output_format all
```

В `out/` появятся `.json` (сегменты и тайминги по словам), `.srt`, `.vtt`,
`.txt`, `.tsv`.

## Результат

Звонок на 37 секунд, модель `small`, 11 сегментов. Тайминги по каждому слову
со скором уверенности:

```
  0.07- 0.39  Добрый       score=0.92
  0.43- 0.89  день,        score=0.94
  0.99- 1.49  сервисный    score=0.92
  1.55- 2.15  центр,       score=0.99
  2.19- 2.41  меня         score=0.85
  2.45- 2.75  зовут        score=0.93
```

**Скорость:** 20,5 с на 37 с аудио — примерно 2× реального времени на CPU,
когда модели уже скачаны.

**Качество на `small`.** Смысл передан, но предлоги и согласование плывут:

| Сказано | Распознано |
|---|---|
| перестало работать вчера вечером | перестал и работать с вчера вечером |
| может подъехать в четверг | может подъехать с четверг |
| в четверг неудобно | с четверг неудобно |

Это ровно тот класс ошибок, который чинится не промптом, а моделью покрупнее:
на `large-v3` такие места заметно лучше. Отдельная категория — имена
собственные (названия компаний, города, модели оборудования): их стоит
подсказывать через `--initial_prompt`, иначе ASR уверенно пишет похожее по
звучанию слово.

## Ограничения, которые всплыли

**Только CPU.** Бэкенд whisperX — CTranslate2, он не поддерживает Metal/MPS.
`--device mps` не заработает, хотя сам torch MPS видит и рапортует как
доступный. На Apple Silicon это значит, что ускорения не будет: для прогона
большого архива нужен сервер, лучше с видеокартой.

**`--compute_type int8` обязателен на CPU.** `float16` на CPU не
поддерживается, падает сразу.

**Диаризации в этом стенде нет.** Для «кто говорил» нужен токен Hugging Face и
принятое соглашение на модель
[`pyannote/speaker-diarization-community-1`](https://huggingface.co/pyannote/speaker-diarization-community-1),
дальше `--diarize --hf_token <токен>`. Токен класть в `.env` (он в
`.gitignore`), а не в команду — иначе осядет в истории shell.

Если источник звонков — виртуальная АТС, сначала проверьте, не отдаёт ли она
**стерео**, где собеседники разведены по каналам. Тогда диаризация не нужна
вообще: каналы разделяются одним вызовом ffmpeg, и самый хрупкий слой пайплайна
просто исчезает.

## Безопасность

whisperX перед установкой проверялся статически: хуков установки в
`pyproject.toml` нет, сетевых вызовов в коде пакета нет, `subprocess`
единственный — вызов ffmpeg для декодирования аудио. Лицензия BSD-2.

В рантайме пакет качает модели с Hugging Face — это его штатная работа.
